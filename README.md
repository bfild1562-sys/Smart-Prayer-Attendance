# Smart Prayer Attendance — Android v2.1 (Google Drive connection test) (offline application)

**This is a real Android source project, upgraded from the supplied `Smart_Prayer_Android_Source_1_1(2).zip`.** It is not the old “Institution workspace URL” launcher. Android UI assets are bundled in the APK and use a Java bridge to an app-private SQLite database.

## What works in this source version

- On-device staff username/password login with remember-me and PBKDF2 password hashing.
- First administrator onboarding, followed by staff registration requiring a **random, single-use, seven-day invitation code** generated by the administrator.
- Staff enable/disable, account activity audit, and audit history identifying the staff member who changed attendance.
- Preserve existing version 1/2 student records and staff accounts through a v3 SQLite migration.
- Add/edit/deactivate/search students; import and export roster CSV.
- Five permanent prayer schedules with start, normal fingerprint deadline, session end, and separately configurable RED MARK late allowance.
- One-touch +/- 1, 2 or 5-minute **linked preview adjustments**; times are saved only when Save is pressed.
- Countdown dashboard showing upcoming or active prayer and green/RED MARK stage.
- Date-based manually recorded PRESENT, RED_MARK, ABSENT, EXCUSED or NOT_RECORDED attendance; effective records constrained to one per student/session/date.
- Required reason for manual attendance changes; append-only correction audit with old/new status, staff and time.
- Create/edit/cancel one-time special programs with their own attendance times. Existing student roster is used for manual event attendance.
- Local monthly report screens, counts of saved attendance records, staff correction log, CSV report export.
- Works locally without requiring a website URL or internet.

## Not implemented in v2.0 (do not mistake for functioning features)

- No ESP32/R503Pro connection yet; no automatic fingerprint scan data enters the database.
- No microSD write, fingerprint template upload/backup, TFT firmware or buzzer control. Those are ESP32 firmware tasks.
- No remote backend, multi-phone shared staff accounts, Google login, Google Drive backup or cloud sync.
- Reports currently summarize *saved attendance entries*, not automatic monthly absent counts or school-wide completion percentages. Historical prayer schedule revisions are audited but a complete per-day session snapshot is a future addition.
- Local schedule windows are restricted to one calendar day. Cross-midnight scheduling requires an additional version.
- No final APK is provided in this archive because the authoring environment lacks the Android SDK, Gradle and APK signing/build tools. The Android Java sources have passed syntax parsing and the JavaScript and SQLite schema have been tested; an actual SDK build and on-device test remain necessary.

## Build an APK using GitHub Actions (no Android Studio required)

1. Create a **private** repository on GitHub and upload the contents of this ZIP, preserving the `android-client/` directory and `.github/workflows/build-android.yml`.
2. Open **Actions → Build Smart Prayer Android APK → Run workflow** (or push to `main`).
3. When the build completes, open the workflow run and download `SmartPrayer-Android-Debug-APK` under Artifacts.
4. Extract the artifact ZIP and transfer the `.apk` to your Android phone. On your own device, allow installation from the application used to open the APK, then install.
5. This is a **debug signed APK for local testing**, not a production release. Retain a stable release signing key for later deployment. If the source APK has a different signing certificate from the prior app, Android will not install it as an update; **export the roster before uninstalling**.

## Build in Android Studio

- Open the `android-client` folder as the Android project.
- Install Android SDK Platform 35 and Android Build Tools 35.
- Android Gradle Plugin 8.7.3 / Gradle 8.9 / JDK 17.
- Choose **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
- Generated APK is under `android-client/build/outputs/apk/debug/`.

## First run

1. Open Smart Prayer Attendance. No URL or link is requested.
2. Select **Register with invitation**; if no staff account exists, the first account becomes the local administrator.
3. Log in. Add/import students and configure each prayer in **Prayers**.
4. To create a staff account, go to **Staff** and generate a code. The staff member uses it during registration **on this device only**.
5. Use **Mark** for manual attendance and **Reports** to review and export records. **RED MARK** is a distinct status.
6. Always export essential data before removing the application or resetting the phone.

## Local storage and security

The local SQLite database stays inside the Android app-private data directory and is not automatically shared between different phones. The app disallows Android system backups. It does not request Google passwords or pretend to synchronize. Phone time is used for displayed countdowns and local records; set correct Android date/time. A future backend and ESP32 with DS3231 will be authoritative for automatic fingerprint attendance.

This is an offline-app development milestone, **not yet a complete production attendance deployment**.
